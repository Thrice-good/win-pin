# win-pin

一个 68×68 的窗口置顶图钉。把图钉拖到任意窗口上松开，图钉就**钉在那个窗口的右上角**，
跟着它一起移动、缩放、最小化。

只为这一件事存在，所以它只有几 MB，常驻内存三十出头，不装运行库，双击即用。

## 用法

| 操作 | 行为 |
| --- | --- |
| 按住图钉拖到某个窗口上松手 | 那个窗口置顶，图钉飞到它的右上角扎住、变红 |
| 单击图钉 | 解除置顶，图钉飞回原位 |
| 按住钉子拖到另一个窗口上松手 | 换成钉那个窗口（旧的自动松开） |
| 按住钉子拖到空白处松手 | 解除置顶，当前位置成为新家 |
| 右键图钉 | 菜单：已钉住 xxx.exe / 解除置顶 / 退出 |
| 被钉的窗口关掉 | 图钉自动松开并飞回原位 |
| 被钉的窗口最小化 | 图钉回原位待着，窗口恢复后自己贴回去 |

位置会记在 `%APPDATA%\win-pin\pos.txt`（首次启动在屏幕右下角，距边缘 26px）。

## 为什么图钉要钉在窗口上

第一版是「钉完弹回右下角」，结果是：图钉在角落里，看不出它钉了谁，也看不出被钉的窗口
现在是什么状态。图钉这个隐喻本身就要求它**待在它钉的东西上**。

所以现在的行为是：松手之后图钉立刻贴到目标窗口右上角，针尖压在上沿，然后跟着窗口走。
窗口一动，图钉就动 —— 这样"哪个窗口被钉住了"是一眼可见的，不需要再去角落确认。

## 为什么不用 PowerToys

PowerToys 的 Always On Top 要装整个套件，常驻几个进程、几百 MB。这个功能本身只需要一次
`SetWindowPos(HWND_TOPMOST)`，用不着那样。

## 实现要点

- **找出鼠标下是哪个窗口**：不用 `WindowFromPoint`。拖动时图钉就压在鼠标正下方，
  `WindowFromPoint` 只会返回图钉自己。改成从 Z 序最顶层往下扫，逐个比对窗口矩形，
  跳过自己、跳过鼠标穿透层、跳过桌面外壳类（Progman / WorkerW / 任务栏）。
- **区分单击和拖动**：系统拖动（`ViewportCommand::StartDrag`）结束后，egui 的
  `outer_rect` 还是旧值，拿它当判据会把拖动误判成单击。改用 `GetCursorPos`
  比较鼠标位移，即时可靠。
- **单击必须单独处理**：`drag_started` / `drag_stopped` 只在位移超过阈值时才出现，
  手不抖的一下点击只会产生 `clicked()`。早期版本只写了拖动那条路，单击完全没反应。
- **右键菜单用 Win32 原生菜单**：egui 的 `context_menu` 画在当前视口内部，
  68px 的窗口会把菜单整块裁掉。`TrackPopupMenu` 不受窗口边界限制。
- **窗口区域裁成图钉轮廓**：`SetWindowRgn` + `CreateEllipticRgn`，椭圆只裹住图钉本身
  （30×42），不是整个 68×68 窗口。这样图钉旁边的透明区域不拦截鼠标，
  贴在窗口角上时也不会盖住标题栏的关闭按钮。
- **那条 1px 边框线**：`DWMWA_BORDER_COLOR = NONE`、清 `WS_CAPTION`、`DwmExtendFrameIntoClientArea`
  归零，四个办法都试过，全无效。真因是 `SetWindowRgn` 设的区域会被 winit 在移动窗口后
  重置回整矩形，于是圆外的顶端露出边框。判据也不能用 `GetWindowRgn` —— 它对被重置的矩形
  同样报 `COMPLEXREGION`。现在每次移动后都无条件重设。
- **置顶会被目标窗口自己改回去**：实测 .NET / WinForms 的窗口在被激活时会丢掉
  `WS_EX_TOPMOST`（Z 序仍在前面，但不再钉住）。所以不能"设一次就信它"，兜底检查时
  每次都确认一遍，丢了就补。

## 低功耗

| 状态 | CPU |
| --- | --- |
| 空闲（未钉住任何窗口） | 0.00%，完全不 `request_repaint` |
| 钉住、目标窗口静止 | 0.00% |
| 目标窗口移动中 | 只在事件到来时重绘，跟随延迟实测 11ms |

关键在跟随的实现方式：一开始用 60ms 定时轮询 `GetWindowRect`，跟手但吃掉 3% CPU；
降到 150ms 又明显跟不上。改成 `SetWinEventHook(EVENT_OBJECT_LOCATIONCHANGE, WINEVENT_OUTOFCONTEXT)`
之后，是**系统在窗口移动时回调我们**，静止时一次都不醒，跟随还更快（11ms）。

留了一个 1 秒的兜底定时器，防止某些环境下收不到事件退化成完全不动。

## 已知限制

- 图钉自己是置顶窗口，所以全屏视频时它会浮在上面。
- 一次只钉一个窗口。钉新的会自动松开旧的，避免桌面上出现几个互不相让的置顶窗口。
- 多显示器且缩放比例不同时，图钉位置按主显示器比例换算，可能偏几十像素。

## 构建

本地不需要装任何东西，推送到 GitHub 后由 Actions 编译：

```
Actions → build-windows-exe → 取 win-pin-windows-x64 产物
```

产物是单个 exe，静态链接 CRT，目标机器不需要 VC++ 运行库。

本地构建（需 rustup + MSVC Build Tools）：

```
cargo build --release --target x86_64-pc-windows-msvc
```
